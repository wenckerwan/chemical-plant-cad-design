# 11 校审、变更与交付检查清单

版本：V1.0｜2026-10-19。以下为【项目约定】，结合S07、S08归纳。

## 1. 校审结论的写法

检查结论采用“通过”“不通过”“待确认”“不适用”，并保存证据。不能把“未检查”“软件未报错”或“肉眼差不多”写成通过。

每项记录检查对象、图号/版本、方法、发现、修改及复核人。草稿、方案、初步设计和施工文件的检查范围分别确定，但不能让阶段排除掩盖本阶段必须解决的问题。

## 2. 设计基础检查

- [ ] 任务、产品规模、运行时间和设计阶段明确。
- [ ] 原料产品组成、危险性和数据来源清楚。
- [ ] 标准版本和适用范围登记，未核验项未冒充已核验。
- [ ] 真实边界、坐标、北向、单位和标高基准一致。
- [ ] 正常、设计、最大最小及特殊工况分开。
- [ ] 假设、缺项和责任人有清单。

## 3. 图种检查

### 3.1 总图

- [ ] 厂界、设施编号、功能分区、周边条件完整。
- [ ] 风玫瑰来源与方向含义明确，未混淆最小频率风与主导风。
- [ ] 道路、回车、入口、装卸、人员和应急通行可实现。
- [ ] 间距有设施分类、适用条款、测量起点和实际值。
- [ ] 管廊、排水、标高、事故水及扩建条件落实到对应图纸。
- [ ] 面积和指标来自同版几何，口径清楚。

### 3.2 PFD

- [ ] 原料、产品、循环、副产和排放可追踪。
- [ ] 物流号、组成、流量和温压与数据表一致。
- [ ] 衡算闭合有计算记录，不只依赖模拟收敛。
- [ ] 主要设备与P&ID及设备表一致。

### 3.3 P&ID

- [ ] 图例、设备、阀门、仪表与线型完整且含义唯一。
- [ ] 管线号、规格、等级和表格对应。
- [ ] 控制、报警、联锁和因果表引用一致。
- [ ] 跨图接续标识成对且唯一。
- [ ] 排气、排液、取样、泄压和界区去向明确。
- [ ] 正常位置与故障动作未混淆。

### 3.4 设备布置

- [ ] 数量、型式、位号与P&ID一致。
- [ ] 设备位置有基准，坐标与标高含义清楚。
- [ ] 各层平面和剖面一致，穿层设备无漏画。
- [ ] 平台、梯子、人孔、操作和维修包络无冲突。
- [ ] 换热器抽芯、机泵拆卸与设备吊装路径可实现。

### 3.5 管道与轴测

- [ ] 连接端点和功能与P&ID一致。
- [ ] 平面、立面、轴测的走向、尺寸、标高对应。
- [ ] 管口方向、DN、连接型式与设备图一致。
- [ ] 间隙计入保温、法兰、阀门、执行器和热位移。
- [ ] 坡向、排气排液、支承和热补偿有依据。
- [ ] 材料表、焊口/管段分界及相关要求可追踪。

### 3.6 设备图

- [ ] 总装、零件、方位及明细表相互一致。
- [ ] 材料、壁厚、接管和制造要求有来源。
- [ ] 管口表、方位、标高和安装接口正确。
- [ ] 强度及检验试验未被未经验证的模型代替。

## 4. 跨文件核查矩阵

|对象|说明书|PFD|P&ID|布置图|数据表/清单|管道/设备详图|
|---|---|---|---|---|---|---|
|设备位号、数量、型式|核对|核对|核对|核对|主数据|核对|
|物流及衡算|主说明|主表达|连接深化|空间约束|主数据|接口|
|管线号、DN、等级|按范围|按范围|主表达|空间对应|主数据|核对|
|仪表与联锁|控制说明|必要信息|主表达|安装接口|主数据|按范围|
|坐标、标高和方位|基准|必要位差|必要位差|主表达|接口数据|核对|
|材料和设计温压|设计依据|操作数据|按范围|按范围|主数据|核对|

“主数据”表示项目指定的维护来源，不表示该文件天然永远正确。发现冲突时依据受控输入和变更记录解决。

## 5. CAD与PDF检查

- [ ] 文件能在目标软件和目标版本打开。
- [ ] 无未处理的缺字体、缺参照、异常代理对象或显示错误。
- [ ] 纸张和方向正确，布局视口比例与标题栏一致。
- [ ] 图层、线型、线宽、字高、尺寸和图块符合项目约定。
- [ ] 关联尺寸反映真实几何，未发现未解释的文字覆盖。
- [ ] 已知长度、坐标、标高和插入单位抽检正确。
- [ ] PDF全图和密集局部可读，无漏页、裁切、乱码或遮挡。
- [ ] 文件名、图号、页号、修订与目录对应。

## 6. 自动化结果怎样验证

### 6.1 真实几何

对STEP/实体文件检查是否有效、实体数、尺寸、体积及关键孔口；对DXF检查单位、实体、图层、块属性及关键长度。检验必须针对保存后的文件，不能只检查生成脚本中的参数。

### 6.2 图面效果

生成最终比例的预览并人工查看。三维模型至少从能暴露主要特征的视角检查；二维图至少检查全图与密集区域。截图成功不等于工程设计通过。

### 6.3 目标软件

脚本生成后，在AutoCAD等实际接收环境中打开并出图，核验字体、参照、块、尺寸和打印。未做这一步时，交付说明应写“未验证目标软件打开/打印”，不能宣称全面兼容。

## 7. 问题分级

|级别|示例|发布处理|
|---|---|---|
|阻断|安全条件无依据、单位错误、关键连接错误、设计边界不清|相关成果不得按完成状态发布|
|主要|设备缺失、平剖面不一致、关键标高或定位缺失|修改并复核|
|一般|非关键标注、索引或格式问题|修订或按阶段批准处理|
|建议|可读性和组织优化|记录并根据影响处理|

不得通过把问题级别调低来绕过必要核查。未关闭问题须在移交单中说明，不能只在个人聊天里提过。

## 8. 变更影响清单

设备增删、位号变化、工况调整、管口移动、材质等级变更和标高调整，应至少检查：计算、模拟、说明书、PFD、P&ID、设备表、管线表、仪表表、布置、管道、结构接口、工程量及采购条件。

修订云线和修订表应一致；已取消对象从图中移除后仍在受控记录中保留追溯。

## 9. 交付包

至少按约定包含：图纸目录、DWG、PDF、必要参照和样式、计算/模拟文件、主表、版本及校审记录、假设缺项说明。交付范围内的文件均可打开且数量、版本一致。

压缩包解压到新目录后检查相对路径和参照；不能只测试原电脑上的工作目录。明确哪些是源文件、交换格式、预览和正式成果，避免接收方错用。

## 10. 校审签署

编制、校核、审核和批准按实际责任分工记录。自动化工具可以执行检查，但不得虚构专业人员签名、审图结论或施工许可。没有批准记录的课程/方案文件保持对应状态。
